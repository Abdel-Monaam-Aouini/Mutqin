# Mutqin (متقن)

On-device Quran recitation checker. The user recites, the engine listens and flags mistakes,
helping them reach itqan (precise mastery). Monorepo: shared C++ core, a CLI to test it, Python
tools, and (later) Android and iOS apps.

**Current scope:** C++17 core `MutqinCore` + `mutqin-cli`. `android/` and `ios/` are placeholders.

## Try it

```
cmake -S . -B build && cmake --build build
python3 tools/quran_text/download.py                       # verified Tanzil text (accept its terms)
./build/cli/mutqin-cli --surah 1 --ayah 1-7                 # expected phonemes with rule tags
python3 tools/prototype/make_posteriors.py /tmp/p.f32 --surah 1 --ayahs 1-7 --scenario skip
./build/cli/mutqin-cli --surah 1 --ayah 1-7 --posteriors /tmp/p.f32   # replay: reports the skipped word
```

With a recognition model, `--wav FILE` and the live microphone (`--mic [--seconds N]`) report mistakes:

```
python3 tools/zipformer/expected_units.py      # once, after downloading the model into models/zipformer_p-quran/
cmake -S . -B build -DMUTQIN_WITH_SHERPA=ON -DSHERPA_ONNX_DIR=/path/to/sherpa-onnx-v1.13.8-...-shared-no-tts
./build/cli/mutqin-cli --surah 5 --ayah 1-8 --model models/zipformer_p-quran/mutqin_model.txt --wav recitation.wav
```

The model is Muno459/zipformer_p-quran (gated, NPL-1.1: free apps only; not in this repository). The manifest
format and the sherpa-onnx backend are described in `docs/ARCHITECTURE.md` ("Recognition backends"); results in
`docs/EVAL_RESULTS.md`.

## Benchmarks

Desktop, Release build, one thread, AMD Ryzen 7 5800H. Real-time factor (RTF) = processing time / audio time
(lower is faster; the target is below 0.3). Details and method: `docs/EVAL_RESULTS.md`.

| Stage | Measurement | RTF |
|---|---|---|
| Log-mel features | 120 s of audio in 0.27 s | 0.0022 |
| Energy VAD | 120 s in 1.6 ms | 0.00001 |
| Aligner + detector, 167 s recitation (700+ words), pushed every 250 ms | 0.77 s total | 0.0046 |
| same, pushed every 40 ms | 2.97 s total (0.7 ms per push) | 0.018 |
| sherpa-onnx + Quran phoneme Zipformer (int8, 4 threads), 49 min of audio | 90 s | 0.031 |

Accuracy on a real correct recitation (49 minutes of surah 5, one reciter): 0.9% of words flagged and 2.5% events
(wrong, skipped, repeated, added) against a 2% target; recall on mistakes injected into the real model output:
skipped 100%, wrong 97%, repeated 99%, added 94%. One reciter, professional audio, synthetic mistakes: learners
and other reciters are not measured yet. Details: `docs/EVAL_RESULTS.md`.
Reproduce: `cmake -S . -B build-rel -DCMAKE_BUILD_TYPE=Release -DMUTQIN_BUILD_BENCH=ON && cmake --build build-rel`,
then `./build-rel/mutqin_bench 120`.

## Working with an AI coding assistant

1. `AGENTS.md` holds the rules (Cursor, Codex, and others read it). `CLAUDE.md` is the entry
   point for Claude Code, with rules in `.claude/rules/` and skills in `.claude/skills/`.
2. Use `START_PROMPT.md` to begin a session; then say "next" for each task.
3. Work one task at a time from `docs/TASKS.md`.

## Checks before a commit

```
python3 -m venv .venv   # or: uv venv .venv
.venv/bin/pip install -r tools/requirements-dev.txt       # pytest, ruff, clang-format (pinned)
.venv/bin/ruff format tools && .venv/bin/ruff check tools
git ls-files '*.h' '*.cpp' | xargs .venv/bin/clang-format -i
cmake -S . -B build -DMUTQIN_WERROR=ON && cmake --build build && ctest --test-dir build --output-on-failure
.venv/bin/python -I -m pytest -q
```

CI (`.github/workflows/ci.yml`) runs the same on every push and pull request: format and lint,
Python tests, and build + test on Linux (gcc, clang, AddressSanitizer + UBSan), macOS and Windows.

**Quran text in CI.** `data/quran/*.txt` is not in the repository. The jobs download it from Tanzil only
if you set the repository Actions variable `TANZIL_TERMS_ACCEPTED=true` (Settings, Secrets and
variables, Actions, Variables), which records that you accept the
[Tanzil Terms of Use](https://tanzil.net/docs/Text_License). The download must match the committed
`data/quran/checksums.txt` or the job fails. Without the variable the tests that need the text are skipped
and the run shows a warning.

## Important

- Quran text always comes from a verified source file (Tanzil), never typed or generated by AI.
- The tajweed spec must be reviewed by a qualified teacher (with ijazah) before release.
- Verify licenses of every dataset, font, and model before commercial use.
